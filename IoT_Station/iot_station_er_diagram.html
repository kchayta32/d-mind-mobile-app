D-MIND · Smart Disaster Monitoring System

IoT Station & Telemetry Subsystem · ER & Data Model

แผนภาพความสัมพันธ์ของข้อมูลและโครงสร้างเอนทิตี (Entity-Relationship Data Model) ครอบคลุมกระแสข้อมูลโทรมาตรแบบรวมศูนย์ (Master Stream), ตารางแยกย่อยเฉพาะโดเมน (Partitions via PostgreSQL Triggers), ระบบวิเคราะห์แจ้งเตือนภัยพิบัติอัตโนมัติ (Automated Alerts) และการควบคุมสิทธิ์ Gateway (API Keys Authentication)

MASTER STREAM & INGESTION

Central sensor_logs Hub

  • Stream Ingestion: รับข้อมูลโทรมาตรครบทุกเซนเซอร์ (AJ-SR04M, PMS5003, GY-521, BME280) จาก ESP32 ผ่าน Mosquitto MQTT & FastAPI Gateway
  • Realtime & Indexing: เปิดใช้งาน Supabase Realtime Replication และสร้าง B-Tree Index บนคอลัมน์ timestamp DESC รองรับ Time-series query ความเร็วสูง
  • Materialized View: รองรับ v_latest_sensor_reading ดึงข้อมูลสถานะล่าสุด 1 แถวเพื่อแสดงผลบน Dashboard มือถือทันที

DATABASE AUTOMATION

Partitioning Triggers

  • sync_sensor_logs(): เมื่อมีข้อมูลใหม่ถูกบันทึกลง sensor_logs ทริกเกอร์จะกระจายข้อมูลลง 4 ตารางย่อยแบบอัตโนมัติ
  • Water Level Evaluation: ประเมินระดับน้ำในตัว: ≥ 100 cm เป็น WARNING, ≥ 140 cm เป็น CRITICAL บันทึกลง water_level_logs
  • AQI Categorization: แปลงค่า PM2.5 เป็นระดับคุณภาพอากาศ (Very Good, Good, Moderate, Unhealthy) บันทึกลง pm_logs
  • Vibration Delta: คำนวณค่าเบี่ยงเบนแรงสั่นสะเทือน |Acc - 1.0g| และตั้งค่า is_anomaly ลง motion_logs

SECURITY & ALARM ENGINE

api_keys & disaster_alerts

  • SHA-256 API Keys: ตรวจสอบสิทธิ์ไคลเอนต์และอุปกรณ์ผ่าน api_keys ด้วยคีย์แฮชที่ไม่เปิดเผยตัวจริง พร้อม Rate Limiting (เช่น 120 RPM)
  • Threshold Alert Engine: บันทึกเหตุการณ์แจ้งเตือนภัยฉุกเฉินลง disaster_alerts เมื่อค่าเซนเซอร์เกินเกณฑ์ความปลอดภัย
  • Lifecycle Tracking: ติดตามสถานะ is_resolved และเวลาคลี่คลาย resolved_at สำหรับแจ้งเตือนไปยังแอปพลิเคชันมือถือ
